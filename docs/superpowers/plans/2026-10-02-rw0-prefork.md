**Architecture:** Two commits on `master`. Task 0.1 anchors the `recordings/` and `clips/` ignore rules to the repository root, commits the three templates those rules hid, and ignores `.worktrees` in git and in the Docker build context, with `tests/test_repo_hygiene.py` guarding all of it. **Spec sentences this plan replaces or narrows because the code proved the premise false:**

- **Section 6, "Changing it restarts that camera's ingest" (and the section 11 `detect_fps` row, "restarts ingest on change").** The only restart path in the code (the supervisor's `rt.recorder.stop(); rt.recorder.start()`, `app.py:224-237`) reuses the `StreamIngestor` objects built at boot, and those copy `upstream_url` and their settings when they are built (`src/rtsp_warden/recorder.py:37-71`). A plain restart would therefore keep the old URL and the old tap rate. In RW-2 and RW-3, "restart" means `request_restart_camera(name)`: stop, rebuild from the current `CameraConfig`, start. Task 0.2's `test_request_restart_rebuilds_the_camera_and_keeps_its_hub` asserts the edited URL reaches the new ingestor.
- **Appendix A.2, "save writes `config.yaml` and hot-adds the camera."** `AppRuntime` had no per-camera API (`build()` loops over all cameras, `app.py:76-136`), and starting or stopping a camera from a web thread would race the supervisor: a concurrent `StreamIngestor.start()` orphans an ffmpeg, and a web-thread stop is seen as a crash and restarted. Hot-add therefore means: the route writes `config.yaml` under the lock, calls `request_add_camera(cam)` and waits on the returned future; the supervisor applies it on the main thread at its next tick.
- **Appendix A.2, "Camera cards show live status (running, restarting with countdown, failed with last ffmpeg error line)."** The data stays where it was (`CameraRuntime.next_restart_at`, `last_error`). New: a start failure such as a taken MJPEG port now lands in `last_error` instead of ending `serve` with a traceback (today two cameras left on the default port 9001 kill `serve` at boot, `app.py:158-161`).

- Task 0.2 uses `queue.SimpleQueue`, not `queue.Queue`: `stop_all()` runs inside the SIGTERM handler on the main thread, and `queue.Queue`'s non-reentrant lock could deadlock there.
- Task 0.2 adds the private helpers `_error_text`, `_submit`, `_fail_pending_requests` and `_supervise_camera` (the last one lets tests pass `now` and removes the three `app.py` E501 lines).
- Task 0.2 makes `start()` survive a per-camera start failure too; the skeleton covered only the supervisor.
- `_apply_add` checks for a duplicate before mutating anything and appends to `cfg.cameras` only when the route has not already done so.
- `_apply_add` and `_apply_restart` call `rebuild_camera_detectors` only when `detectors_enabled` (as `_build_detectors` does for `--no-detectors`).

- `_drain_requests` also catches `SystemExit`, which `_build_camera_runtime` raises for an unknown proxy mode, so a bad hot-add cannot end `serve`.
- A camera that is added or rebuilt but cannot start stays in `cameras` and `cfg.cameras`; its future carries the start error and the supervisor retries it with backoff.
- `stop_all()` fails queued requests with `RuntimeError("runtime stopping")`, and a request submitted after `stop_all()` fails at once.
- The proxy restart branches clear `proxy_restart_at` before calling `start()`, so a failing start backs off (1 s, 2 s, 4 s ... 60 s) instead of retrying every 0.5 s tick.
- The `run_forever` test stops the loop by setting `runtime.stop` from a fake `sleep`, not by raising a sentinel, so "returns normally" is itself the assertion.

A fresh checkout (a clone, CI, or a ``git worktree``) contains only what git tracks. These tests

import subprocess
from pathlib import Path

import pytest

# Directories whose files must always be committable, and the file types that live in them.
SOURCE_DIRS = ("src", "tests", "migrations")
SOURCE_SUFFIXES = frozenset({".py", ".html", ".js", ".css", ".mako", ".cfg", ".names", ".xml"})

)


def _git(*args: str, stdin: str | None = None) -> subprocess.CompletedProcess[str]:
    return subprocess.run(
        ["git", "-C", str(REPO_ROOT), *args],
        input=stdin,
        capture_output=True,
        text=True,
        check=False,
    )


def _source_files() -> list[str]:
    files: list[str] = []
    for top in SOURCE_DIRS:
        base = REPO_ROOT / top
        if not base.is_dir():
            continue
        for path in base.rglob("*"):
            if "__pycache__" in path.parts or not path.is_file():
                continue
            if path.suffix in SOURCE_SUFFIXES:
                files.append(path.relative_to(REPO_ROOT).as_posix())
    return sorted(files)

def test_no_source_file_is_hidden_by_an_ignore_rule() -> None:
    files = _source_files()

    # --no-index checks the ignore rules themselves, so a tracked file still counts: a rule that
    # matches it would silently skip every new sibling file a later `git add` should pick up.
    result = _git("check-ignore", "--no-index", "--stdin", stdin="\n".join(files) + "\n")
    assert result.returncode in (0, 1), result.stderr
    hidden = result.stdout.split()
    assert hidden == [], f"source files matched by an ignore rule: {hidden}"

  Contract the tracks rely on:
  - `request_*` only enqueue: they never block, never raise, and are safe from any thread, including before
    `start()` (requests wait for the first `run_forever` tick). Callers that need the outcome wait on the
    future (`fut.result(timeout=...)` from a sync route running in the threadpool).
  - The future resolves to `None` on success. It fails with `ValueError("camera 'x' already exists")` (add of a
    running name) or `ValueError("camera 'x' not found")` (remove/restart of an unknown name); with the start
    error (for example `OSError`) when the camera was added or rebuilt but could not start, in which case the
    camera STAYS in `cameras` and `cfg.cameras` and the supervisor retries it with backoff; with
    `RuntimeError("runtime stopping")` once `stop_all()` has run.
  - add: appends `cam` to `cfg.cameras` only when no entry of that name exists (the add route may append
    first), publishes the new `CameraRuntime` before starting it, calls `rebuild_camera_detectors(name)` when
    `detectors_enabled`, then `_start_camera`.
  - remove: unpublishes, stops, tears down runner `detector_<name>` and drops it from `detector_runners` and
    `frame_tap_dispatcher.consumers` under `_detector_lock`, then removes every `cfg.cameras` entry of that
    name in place (`cfg.cameras[:] = ...`). Recordings on disk are untouched.
  - restart: stops the old runtime, rebuilds from the `cfg.cameras` entry of that name (falls back to the old
    `CameraConfig`), passes `hub=old.hub` (kept for MJPEG, ignored otherwise), replaces the `CameraRuntime`
    object in `cameras`, calls `rebuild_camera_detectors(name)` when `detectors_enabled`, then starts it. The
    new object has fresh backoffs and zeroed schedules. Code holding the old `CameraRuntime` must look it up
    again with `find_camera`.

    # Per-camera lifecycle: request_* (any thread) -> _drain_requests (main thread)
    # ------------------------------------------------------------------

    def request_add_camera(self, cam: CameraConfig) -> Future[None]:
        """Queue a hot-add of *cam*; returns at once, the future resolves on the next tick.

        The future fails with ValueError when a camera of that name is already running.
        A camera that is added but cannot start (a taken port, say) stays configured, the
        supervisor keeps retrying it, and its future carries the start error.
        """
        return self._submit("add", cam.name, cam)

    def request_remove_camera(self, name: str) -> Future[None]:
        """Queue stopping camera *name* and dropping it from the runtime and cfg.cameras."""
        return self._submit("remove", name, None)

    def request_restart_camera(self, name: str) -> Future[None]:
        """Queue a stop, rebuild from the current CameraConfig, and start of camera *name*."""
        return self._submit("restart", name, None)

    def _submit(
        self, kind: Literal["add", "remove", "restart"], name: str, cam: CameraConfig | None
    ) -> Future[None]:
        fut: Future[None] = Future()
        self._requests.put(_RuntimeRequest(kind=kind, name=name, camera=cam, future=fut))
        return fut

    def _drain_requests(self) -> None:
        """Apply queued lifecycle requests in FIFO order. Main thread only; never raises."""
        while not self.stop:
            try:
                req = self._requests.get_nowait()
            except queue.Empty:
                return
            if not req.future.set_running_or_notify_cancel():
                continue  # the caller cancelled it before it ran
            try:
                if req.kind == "add":
                    if req.camera is None:
                        raise ValueError("add request without a camera")
                    self._apply_add(req.camera)
                elif req.kind == "remove":
                    self._apply_remove(req.name)
                else:
                    self._apply_restart(req.name)
            except (Exception, SystemExit) as exc:
                # SystemExit too: _build_camera_runtime raises it for an unknown proxy mode,
                # and a bad hot-add must never end serve.
                log.warning("[supervisor] %s %s failed: %s", req.kind, req.name, exc)
                req.future.set_exception(exc)
            else:
                log.info("[supervisor] %s %s done", req.kind, req.name)
                req.future.set_result(None)

    def _apply_add(self, cam: CameraConfig) -> None:
        """Build, publish, wire detectors for, and start a new camera."""
        if self.find_camera(cam.name) is not None:
            raise ValueError(f"camera {cam.name!r} already exists")
        rt = self._build_camera_runtime(cam)
        # The add-camera route may already have appended this camera to cfg.cameras.
        if not any(c.name == cam.name for c in self.cfg.cameras):
            self.cfg.cameras.append(cam)
        # Publish before starting, so stop_all() (signal handler) always sees its processes.
        self.cameras = [*self.cameras, rt]
        if self.detectors_enabled:
            self.rebuild_camera_detectors(cam.name)
        self._start_camera(rt)

    def _apply_remove(self, name: str) -> None:
        """Unpublish and stop a camera, drop its detector runner, forget its config."""
        rt = self.find_camera(name)
        if rt is None:
            raise ValueError(f"camera {name!r} not found")
        # Unpublish first, so the supervisor stops supervising it, then stop it.
        self.cameras = [r for r in self.cameras if r is not rt]
        self._stop_camera(rt)
        runner_name = f"detector_{name}"
        with self._detector_lock:
            for runner in self.detector_runners:
                if runner.name == runner_name:
                    try:
                        runner.teardown()
                    except Exception:
                        log.warning("detector runner teardown failed", exc_info=True)
            self.detector_runners = [r for r in self.detector_runners if r.name != runner_name]
            if self.frame_tap_dispatcher is not None:
                self.frame_tap_dispatcher.consumers = tuple(
                    c
                    for c in self.frame_tap_dispatcher.consumers
                    if getattr(c, "name", None) != runner_name
                )
        self.cfg.cameras[:] = [c for c in self.cfg.cameras if c.name != name]

        old = self.find_camera(name)
        if old is None:
            raise ValueError(f"camera {name!r} not found")
        self._stop_camera(old)

        # they are built, so an edited CameraConfig only takes effect in a new recorder.
        cam = next((c for c in self.cfg.cameras if c.name == name), old.camera)
        new = self._build_camera_runtime(cam, hub=old.hub)
        self.cameras = [new if r is old else r for r in self.cameras]
        if self.detectors_enabled:
            self.rebuild_camera_detectors(name)
        self._start_camera(new)

    def _supervise_camera(self, rt: CameraRuntime, now: float) -> None:
        """One supervisor pass over one camera: retention, then ingest and proxy restarts.

        The restart schedules live on the CameraRuntime (next_restart_at, proxy_restart_at),
        so a removed or rebuilt camera takes its schedule with it.

                if sp.proc is None or sp.proc.poll() is not None:

                    all_running = False
                    break
                if not sp.proc.is_running():
                    all_running = False

                rt.rec_backoff.reset()
                rt.mark_healthy()
